# Світлофор. Лабораторна робота №3

**Виконала:** Даскалюк

**Контрольна точка:** CP3 — автоматичний світлофор із керованим життєвим циклом часової поведінки.

## Мета

Навчитися додавати до React-застосунку поведінку в часі: запускати й зупиняти таймер через `useEffect`, коректно виконувати функцію очищення (cleanup), керувати залежностями ефекту та відображати зміни стану за допомогою CSS-переходу.

## Що реалізовано

- Ручний режим з ЛР2 збережено: клік на лампу робить сигнал активним і збільшує його лічильник.
- Автоматичний режим: кнопки «Запустити» та «Зупинити» змінюють стан `isAutomatic`.
- Цикл фаз `red → yellow → green → yellow → red` із тривалістю фази 3 секунди.
- Одночасно працює не більше одного таймера: він створюється в `useEffect` і зупиняється функцією очищення.
- Під час автоматичного режиму ручний вибір вимкнено, автоматичні кроки не збільшують лічильники ручних натискань.
- Після «Зупинити» поточний сигнал залишається видимим, ручна взаємодія й статистика працюють далі.
- Орієнтація vertical / horizontal перемикається без скидання фази й статистики.
- Активна лампа змінюється з помітним CSS-переходом (`opacity`, `transform`, `box-shadow`).

## Структура компонентів

```
App
└── TrafficLights   (стан: phaseIndex, isAutomatic, clicks, orientation)
    ├── Light × 3
    └── StatsBar
```

| Компонент | Відповідальність |
|-----------|------------------|
| `TrafficLights` | Єдиний власник стану, ефект із таймером, обробники подій |
| `Light` | Показує лампу, викликає `onSelect(color)`, має CSS-перехід |
| `StatsBar` | Статистика, режим, кнопки «Запустити» / «Зупинити», перемикач орієнтації |

## Ключові рішення

- **Єдине джерело фази.** Зберігається `phaseIndex`, а видимий сигнал обчислюється як `CYCLE[phaseIndex]`. Індекс потрібен, бо `yellow` зустрічається в циклі двічі. Під час ручного вибору yellow використовується позиція 1.
- **Таймер у ефекті.** «Запустити» лише ставить `isAutomatic = true`, а `useEffect` створює `setInterval` і повертає `clearInterval`. Інтервал не створюється в обробнику кліку.
- **Залежності `[isAutomatic]`.** Від цього значення залежить, чи існує таймер. Константа тривалості лежить поза компонентом, а попередня фаза береться функціональною формою `setPhaseIndex((previous) => ...)`, тому `phaseIndex` у залежностях не потрібен і інтервал не перестворюється щокроку.
- **Strict Mode.** Додатковий цикл «налаштування → очищення → налаштування» не створює другого таймера, бо кожне налаштування має власне очищення.
- **Анімація як відображення стану.** CSS `transition` залежить від пропса `active` і не визначає наступну фазу. Без CSS послідовність працює так само.

## Запуск

```bash
npm install
npm run dev
```

Відкрийте адресу з терміналу (зазвичай `http://localhost:5173`).

## Перевірка

1. Ручні кліки red → green → green → yellow дають Red 1, Yellow 1, Green 2, всього 4.
2. «Запустити»: сигнал проходить цикл у правильному порядку, лічильники не змінюються.
3. Кілька разів «Запустити → Зупинити → Запустити»: швидкість цикла не зростає.
4. Після «Зупинити» ручні кліки знову збільшують лічильники.
5. Перемикання орієнтації не скидає фазу й статистику.

## Висновок

Під час роботи було засвоєно різницю між обробником події та ефектом, життєвий цикл `useEffect` (налаштування, залежності, очищення), керування таймером через стан режиму, використання єдиного джерела фази з похідним сигналом і візуальні переходи, керовані станом React.Після запуску відкрийте адресу, яку покаже Vite (зазвичай `http://localhost:5173`).
