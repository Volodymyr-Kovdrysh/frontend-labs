# Світлофор. Лабораторна робота №4

**Виконав(ла):** Даскалюк

**Контрольна точка:** CP4 — багатомаршрутний SPA зі спільним станом світлофора.

## Мета

Організувати React-застосунок як SPA з кількома маршрутами та винести стан світлофора до спільного власника (Context), бо одні й ті самі дані потрібні різним гілкам маршрутів.

## Маршрути

| URL | Сторінка |
|-----|----------|
| `/` | Головна |
| `/traffic-light` | Світлофор: ручний вибір, запуск/зупинка, орієнтація |
| `/stats` | Статистика (лише читання) |
| `/status` | Додатково: компактний статус (лише читання) |
| `*` | Сторінка 404 |

## Структура

```
BrowserRouter
└── TrafficLightsProvider   (стан, таймер, дії)
    └── App → Routes
        └── AppLayout (NavLink + Outlet)
            ├── HomePage
            ├── TrafficLightPage → TrafficLights, ControlsPanel
            ├── StatsPage        → StatsBar
            ├── StatusPage
            └── NotFoundPage
```

## Ключові рішення

- `TrafficLightsProvider` змонтований вище за маршрути, тому стан і таймер не скидаються при навігації.
- Context містить тільки предметну область світлофора: сигнал, лічильники, орієнтацію, режим і дії.
- `Light`, `TrafficLights`, `StatsBar` не залежать від Router: дані приходять через props зі сторінок.
- `currentSignal` і `totalClicks` обчислюються як похідні значення.
- Життєвий цикл таймера з ЛР3 (`useEffect` + `clearInterval`, залежність `[isAutomatic]`) перенесено в провайдер без змін.
- Збереження стану між перезавантаженнями браузера не реалізовано (тема ЛР5).

## Запуск

```bash
npm install
npm run dev
```

## Висновок

Освоєно клієнтську маршрутизацію (`BrowserRouter`, `Routes`, `NavLink`, `Outlet`), поділ на сторінки, макет і презентаційні компоненти, а також Context як спосіб спільного володіння станом кількома маршрутами.
